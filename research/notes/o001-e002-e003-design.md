## 2. E002 design

### 2.1 Sample, strata, exclusions
- **Sample.** `generate_layouts(n, sealed seed)` on the T0075 snapped generator (0.5 mm design grid). With n a multiple
  of 30, every (family × dies 2-6) stratum holds n/15 layouts (checked by `sample_diverse`). The top decile k = n/10 and
  the top quintile w = n/5 are whole numbers.
- **Rounding rule (declared in advance).** k = max(1, round(0.1 n)), w = max(1, round(0.2 n)), Python round-half-to-even.
  It is exact at the registered n, so it is never invoked.
- **Subsets** are fixed by generation order within each stratum, never by any computed value:
  - **frequency subset:** `freq_per_stratum` per stratum (0 in (a), 1 in (b));
  - **k\*−1 subset:** `low_per_stratum` = 1 per stratum, plus the checked layouts;
  - **check subset:** the first layout of each `check_strata` entry. (a): u_shaped:6 (largest dev bias, 1.9 %). (b):
    interleaved:6, u_shaped:6, side_by_side:2, which complement the dev VM layouts (interleaved:2, u_shaped:2,
    side_by_side:6).
- **Exclusions: none.** A DRC or lattice failure, a crashed child, or a non-finite value fails a sanity check, and the run
  is invalid. Nothing is dropped.
- **Seeds.** The sealed seed comes from `mfos exp run`; the runner refuses to run without it. Bootstrap: seed 20261008,
  n_boot 2000, paired percentile.

### 2.2 Models, levels, provenance
- **L1:** `physics.peec.loop_inductance` at the default mesh (4 mm), 5/20/80 MHz. At hmax 2/1/0.5 mm (20 MHz) for F3
  only.
- **L2:** `solvers.l2_layout.loop_inductance`. k* = 1 (0.25 mm) on every layout; 0.5 mm on the k*−1 subset; 0.125 mm on
  the check subset. One mesh per call, graded to max(100 MHz, f_max), so L(20 MHz) does not depend on the frequency list.
- **Execution.** Fresh child per solve, 4 jobs × 8 threads (the VM cost basis), longest first within each phase.
- **Provenance.** tool_version and `source_sha256()` (l2_layout + l2_core) in `run.tools`; every child must report the
  same values. Under D0004 no FastHenry binary is needed; `uv sync` suffices.

### 2.3 Order of work (fail early; repair item 2)
0. **Spec and config.** Every key set and typed; check strata valid; declared sanity checks equal the runner's set;
   declared metrics equal `metric_plan(config)`. A mismatch raises before anything is generated.
1. **Layouts** generated; `all_drc_valid` evaluated (DRC; traces, planes and die footprints on the lattice at 0.5,
   0.25 and 0.125 mm).
2. **Dry pass.** The full `analyse()` runs on placeholder L1/L2 values (an exact geometric ladder) for the real task
   list. It covers three paths: a valid run, a run aborted at the phase-1 gate, and a run with one failed solve. It
   asserts:
   - no exception;
   - all 8 sanity checks reported;
   - the placeholder run passes every check except the real preconditions;
   - every required metric is emitted, finite, and nothing undeclared is emitted;
   - the primary metrics carry CIs;
   - the phase-1 gate passes.

   A failure raises **before any solve**. A real precondition failure (DRC or lattice, or E001 runner sha) ends the run
   with every check reported and no solve.
3. **L1** at the default mesh on every layout (seconds); the fine meshes run in a background thread.
4. **Phase 1:** k*+1, k*, k*−1 of the checked layouts, C1 via `l2`, and C1 via `l2_layout`. **Gate:**
   - `l2_converged` on the checked layouts;
   - `l2_reference_valid` and `l2_layout_reference_valid`;
   - `l2_solver_ok` and `l2_provenance_consistent` on these solves.

   On failure, no phase-2 solve starts. Every sanity check is reported, failing where not evaluated. No metric is
   computed, and the runner exits 0, so the status is "complete" with failed checks and the evaluator refuses the
   evidence. A non-zero exit would turn the status into "error" (`mfos/experiments.py`, line 121) and hide the reason.
5. **Phase 2:** every other solve. The per-layout rows artifact is written first, then the analysis.

### 2.4 Sanity checks (each can fail on its own)
| check | fails when |

| `l2_layout_reference_valid` (new) | C1 assembled from the **l2_layout internals** (filament-bundle wire, plane slab on the shared grid, precorrected-FFT wire↔grid operator, `LayoutSystem`, GMRES and the a-posteriori bound; refinement 1, 0.7 mm cells, 20 MHz, exactly as `test_c1_layout_internals_vs_l2_solve_same_refinement`) differs from `l2.solve` at the same refinement by > 0.5 % (the unit test's tolerance), or from E001's closed form by > 2 %; or GMRES fails; or the layout path's stated solver_tol_rel_L exceeds the 0.5 % comparison tolerance, or l2's is ≥ 1e-5 (as the unit test asserts) |
| `l2_converged` | a checked layout has \|d2\| + tol(k*) + tol(k*+1) ≥ 1 % or does not contract (d2/d1 ∉ (0, 1)); or a k*−1 layout has predicted step r_max\|d1\| ≥ 1 %. Not fully evaluated when the run is aborted, and then it fails |
| `l2_solver_ok` | a GMRES flag ≠ 0; solver_tol_rel_L > 1e-3 (k*, k*−1) or > 2e-3 (k*+1); **represented copper area ≠ exact area** (> 1e-9 relative, `mesh_params.area_rel_err`); **die shorts ≠ one per die or spanning two nets** (`mesh_params.die_short_nets`); a solve failed or never ran |

| `sample_diverse` | CV(L2 at 20 MHz) < 0.3 (F2) on the snapped generator, or the strata are unbalanced |

**What `l2_layout_reference_valid` does not cover (stated, not hidden).** It does not exercise the layout front end:
lattice mapping, bilinear contacts, die shorts, the three-slab stack. Those are covered in-run by `all_drc_valid` and the
area and die-short checks of `l2_solver_ok`. Offline they are covered by unit tests (`test_every_net_area_exact_and_every_feature_on_the_lattice_at_every_refinement`,
`test_die_short_connects_only_its_own_net`, `test_layout_mapping_dc_resistance_closed_form`,
`test_layout_loop_inductance_vs_independent_partial_inductance_sum`). The source sha in provenance ties the run to the
tested code.

**Thin margin of `l2_converged` (repair item 8; risk stated, not resolved).** Facts from dev VM data:
\|d2\| + tol(k*) + tol(k*+1) was 0.63 % (interleaved:2), 0.84 % (u_shaped:2) and 0.88 % (side_by_side:6) against the
1 % gate. interleaved:6 and u_shaped:6 have never been solved at k*+1. The founder's runs into
`research/l2_layout_vm2/` were not on `main` when I finished. Inference: a step ~15 % larger than the largest seen so far
fails the gate. The gate is not weakened. What changed is the cost of a failure: phase 1 runs first, so a failure costs
~11 CPU-h in (a) and ~32 CPU-h in (b), not the whole run. If the vm2 data show a 6-die step near 1 %, the founder can
choose other check strata before registration. That is a choice on dev data, not on the sealed sample.

**"Converged" means a small step, not a small error.** The residual bias at k* (1.3-1.9 % on dev layouts) can exceed
conv_tol while the gate passes. The bias metrics below report it, and it is never treated as zero.

### 2.5 Metrics
**Primary** (A2-A5, K1-K3; 20 MHz; L1 at the default mesh vs L2 at k*):
- `spearman_rho_Lloop` and `mape_Lloop`, with bootstrap CIs;
- `top_decile_recall`, point value, CI reported.

**L2 bias at k\*** (founder notes; never treated as zero). Model: geometric lateral ladder, L_k = L∞(1 + c q^k).
- Definitions: d1 = (L_k* − L_k*−1)/L_k*, d2 = (L_k*+1 − L_k*)/L_k*, r = d2/d1.
- Bias: β = −d2/(1 − r), with L2(k*) = L∞/(1 − β). Derivation: L∞ = L_k*(1 + d2/(1 − r)). The reviewers verified this
  by hand and on a synthetic ladder. The selftest recovers β of the checked layouts to 1e-9.
- **Checked layouts:** their own β, from three levels.
- **Two-level layouts** (k*−1 subset):
  - point estimate −d1 r̄/(1 − r̄);
  - interval: the value at r_min and at r_max, **ordered by sign**. r/(1 − r) increases on (0, 1), so for d1 > 0 the ends
    swap. This fixes the T0094 finding.
- **Band** [β_lo, β_hi] = [min of the lower ends − 0.5 pt, max of the upper ends + 0.5 pt]. **It is measured on the
  refinement subset only** (15 layouts, 1-3 of them at three levels).
  - Using it for the other 15 (a) or 75 (b) layouts **assumes** their bias lies in the range spanned by the measured
    ones. This holds if the per-layout bias is exchangeable across the population. The subset is chosen by generation
    order within each stratum, independently of any value, so it is a fair sample of each stratum. But each stratum
    contributes one measured layout, so exchangeability *across* strata is part of the assumption.
  - Under exchangeability, a new layout falls outside [min, max] of m measured ones with probability 2/(m + 1) ≈ 12.5 %
    at m = 15, before the margin (inference, order statistics).
  - The two-level intervals also assume that every layout's contraction lies in [r_min, r_max] measured in-run. In (a)
    that is one value (dev: 0.61-0.62 on 3 families).
  - **`l2_bias_band_loo_coverage`** measures the transfer in-run: the share of measured layouts whose own interval lies
    inside the band built without them.
  - The descriptions no longer say "rigorous". `refbound` is **conditional on the band**.
- **Bias-corrected metrics** (`*_l2corr`): against L2(1 − β_i). Measured layouts use their own estimate; the others use
  the mean of their stratum's measured layout, else the family's. This is a change from attempt 1's family mean,
  because the founder reports a family-dependent offset and the stratum is the closer match.
- **`mape_Lloop_refbound_lo/hi`:** bootstrap bounds of the mean over layouts of the min / max over the band of
  |L1/(L2(1 − β)) − 1|. `ape_range` was verified analytically and by brute force (T0094, T0095).

**Near ties.** τ = max(1 %, β_hi − β_lo). Reported: `top_decile_recall_band_lo/hi`, which count L1-top layouts within τ
of L2's top-quintile boundary as out or in, and `l2_near_tie_pair_frac`. Spearman is barely affected: near-tie pairs have
adjacent ranks, so each one moves ρ by O(1/n²) (inference).

**k\* vs k\*+1 on the checked subset.**
- `ape_shift_kstar_to_kstar1_max` is reported in both envelopes.
- `check_pairs_concordant_frac` exists only with ≥ 2 checked layouts, so it is declared only in (b).
- A Spearman or MAPE over 1-3 layouts would be meaningless, so the sensitivity is carried to all n through the bias
  model.

**Secondary metrics:**
- within-family Spearman;
- diversity: `cv_L2`, `cv_loop_area`;
- F4: L1's own 5/80 vs 20 MHz rank stability in both envelopes; L2 at 5/80 MHz on the frequency subset in (b) only;
- F3: residual Spearman with loop area, plane distance and die count, for L1 at 4 mm and at 0.5 mm, plus
  `l1_mesh_bias_spearman_dies`;
- cost.

F3 limitation (fact): the stack is fixed by the generator, so the plane-distance proxy varies only through the wire loop
height.

**Envelope (a) honestly lacks:** L2 F4 data, the pair-concordance metric, and a three-level bias measurement on more than
one family.

## 3. Power analysis

**Method.** Simulation: `research/scripts/e002_power.py`, 400 replicates per cell, 1000 bootstrap resamples.
- **Population structure.** 1500 dev-seed layouts (seed 990001, unsealed). Their L1 values stand in for the true
  population: family clustering, die trend, CV 0.37.
- **Error model.** log L1 = log T + μ + a_fam + 0.003(dies − 4) + σε, with a_fam = ±2 %. The reference is
  L2 = T(1 + β), with β_fam = 1.3-1.9 % ± 0.25 %.
- **Sampling.** Stratified, n/15 per stratum. The statistics are exactly those in the runner.
- **K1 power.** Simulation never reached ρ < 0.89, so K1 power uses the Fisher-z approximation with Bonett-Wright
  variance (1 + ρ²/2)/(n − 3) (Bonett & Wright, Psychometrika 65 (2000) 23).

**Spearman (A2 lower CI ≥ 0.85; A3 point ≥ 0.90).** Population ρ is set by σ:

| σ (log scatter) | 0.04 | 0.06 | 0.08 | 0.10 | 0.13 | 0.17 |
|---|---|---|---|---|---|---|
| population ρ | 0.989 | 0.977 | 0.962 | 0.944 | 0.918 | 0.888 |
| P(A2), n = 30 | 1.00 | 0.97 | 0.79 | 0.50 | 0.16 | 0.04 |
| P(A2), n = 60 | 1.00 | 1.00 | 0.99 | 0.89 | 0.48 | 0.10 |
| P(A2), n = 90 | 1.00 | 1.00 | 1.00 | 0.99 | 0.68 | 0.12 |
| P(A3), n = 30 / 90 | 1 / 1 | 1 / 1 | 1 / 1 | 0.98 / 1 | 0.76 / 0.85 | 0.37 / 0.26 |

- **K1 (upper CI < 0.80) with power ≥ 0.8** needs ρ ≤ 0.48 (n = 30), ≤ 0.60 (n = 60) or ≤ 0.64 (n = 90).
- **Indecision band (inference)**, where neither A2 nor K1 is reached with probability ≥ 0.8:
  - n = 30: ρ ∈ (0.48, ~0.96);
  - n = 90: ρ ∈ (0.64, ~0.94).
- Median 95 % CI width at ρ = 0.977: 0.074 (n = 30), 0.030 (n = 90).
- Because of family clustering, a pooled ρ below 0.89 needs σ > 17 %. K1 is therefore only reachable if L1 is grossly
  wrong. The realistic risk is an inconclusive A2 for ρ in 0.90-0.94.

**MAPE (A4 upper CI ≤ 0.12; K2 lower CI > 0.20)**, at σ = 0.06:

| population MAPE | 0.050 | 0.076 | 0.093 | 0.113 | 0.145 | 0.203 | 0.265 |
|---|---|---|---|---|---|---|---|
| P(A4), n = 30 | 1.00 | 0.98 | 0.67 | 0.10 | 0 | 0 | 0 |
| P(A4), n = 90 | 1.00 | 1.00 | 0.98 | 0.18 | 0 | 0 | 0 |
| P(K2), n = 30 / 90 | 0 | 0 | 0 | 0 | 0 | 0.07 / 0.05 | 1.00 / 1.00 |

The dev planning value of MAPE is 0.114 against L2(k*) and 0.098 against the corrected L2. It comes from three layouts,
so its own uncertainty is large. The value sits where A4 has low power at any affordable n. Because the L2 bias shifts
MAPE by ~1.5 points, the reference band of §2.3 matters (decision 2).

**Top-decile recall (A5 ≥ 0.7, K3 < 0.5; point).**
- **Resolution:**
  - n = 30: k = 3, w = 6. A5 needs 3/3, and K3 fires at ≤ 1/3.
  - n = 90: k = 9, w = 18. A5 needs 7/9, and K3 fires at ≤ 4/9.
- **Simulated P(A5):**
  - n = 30: 0.97 / 0.87 / 0.85 / 0.78 at ρ = 0.977 / 0.962 / 0.944 / 0.918;
  - n = 90: 1.00 / 1.00 / 0.99 / 0.98.
- P(K3) ≤ 0.03 everywhere in the simulated range.

**Is there a decidable n?** Yes, at plausible effect sizes. Both envelopes decide A2/K1 and A4/K2 when L1 is clearly
good (ρ ≥ 0.96, MAPE ≤ 0.08) or clearly bad (MAPE ≥ 0.25, ρ ≤ 0.48-0.64). n = 90 narrows the A2 indecision band to
ρ ≈ 0.90-0.94 and the A4 band to MAPE ≈ 0.10-0.12. I do not report the task as blocked. I state plainly that A4 may well
land in its indecision band at either envelope.

## 5. E003 design
- **Unit timed:** one `loop_inductance(layout, [20 MHz])` call, Layout → L_loop including discretisation, default mesh.
- **Sample:** sealed seed, `generate_layouts(150)`, 10 per stratum, 3 repeats in a seeded shuffled order (n_evals 450).
- **Warm-up:** 5 calls on a dev-seed layout, declared and excluded. No other exclusion.
- **Threads.** The BLAS/OpenMP variables are set to 1 before numpy is imported. `XLA_FLAGS="--xla_cpu_multi_thread_eigen=false"`.
  - **Why the other token was dropped, not prefixed (fact, this machine, jax 0.11.2):** with
    `XLA_FLAGS="--xla_cpu_multi_thread_eigen=false --intra_op_parallelism_threads=1"`, importing JAX aborts with
    `F… parse_flags_from_env.cc:234] Unknown flag in XLA_FLAGS: --intra_op_parallelism_threads=1`.
    `intra_op_parallelism_threads` is a TensorFlow session option, not an XLA flag. With only the first token, JAX
    imports and computes normally. So "every token carries `--`" is met by keeping only valid flags.
  - `single_thread_enforced` now also fails if any XLA_FLAGS token lacks `--`.
- **Pinning.**
  - Linux: `sched_setaffinity` to one CPU, checked (affinity set of size 1).
  - **macOS cannot pin a process to a core, and cannot choose P- or E-cores.** The scheduler decides. The runner records
    this in `run.tools` (`core_pinning`, `cores`: "4 x Super, 6 x Efficiency" on this Apple M5) and in the check's
    detail.
  - CPU/wall ≤ 1.1 catches extra threads, not E-core placement. An E-core only slows the loop, which is conservative for
    A6 (a ≤ criterion). Running E003 on Linux, where affinity is enforced, gives the cleaner claim.
- **Metrics:**
  - `l1_eval_ms_p50` (A6 reads the point) and p90, each with a cluster-bootstrap CI over layouts;
  - the 6-die p50 and `cpu_wall_ratio`;
  - the CPU model and core configuration, recorded.

## 7. What would show this design wrong
- **Cost model.** `cpu_hours_total` exceeds the estimate by > 25 %, or the timeout fires.
- **Reference not converged on the sealed sample.** `l2_converged` fails, or the in-run contraction is outside 0.5-0.7.
  Either undermines the bias model.
- **The band does not transfer.** `l2_bias_band_loo_coverage` well below ~0.85. The conditional refbound reading is then
  void.
- **Clustering hides a poor model.** `spearman_rho_within_family` far below the pooled ρ. Reported, not gated.
- **F3 rule (pre-registered):**
  - A die-count flag is raised when the CI of `resid_spearman_dies` excludes 0.
  - It is attributed to L1 discretisation only if the CI of `resid_fine_spearman_dies` includes 0 *and* that of
    `l1_mesh_bias_spearman_dies` excludes 0 with the same sign.
  - Otherwise it points at missing physics.
  - The dev data (§1) suggest the latter. That is speculation, from 3 layouts.
